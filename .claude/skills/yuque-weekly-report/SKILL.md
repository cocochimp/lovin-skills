# 语雀周报生成

根据用户本周在语雀新增的文档，自动分类整理并生成结构化周报，最终发布到指定语雀知识库。

## 工作流程

### Step 1: 确认周报目标知识库

向用户确认周报要写入哪个语雀知识库。可通过以下方式获取：

- 用户直接提供语雀知识库 URL → 调用 `skylark_resolve_url` 解析得到 `book_id`
- 用户提供知识库名称 → 调用 `skylark_user_book_list` 查找匹配的知识库
- 若用户未指定，列出用户的知识库让其选择

### Step 2: 获取本周新增文档

1. 调用 `skylark_user_recent` 获取用户最近操作记录（设置 `type: "doc"`，`limit: 50`）
2. 通过 `date` 命令获取当前日期，计算本周一（周一为起始日）的日期
3. 筛选出**本周内创建**的文档（根据 `created_at` 字段过滤）
4. 如果最近记录不足以覆盖本周，可结合 `skylark_doc_list` 补充查询用户常用知识库

### Step 3: 读取文档内容并分类

对每篇本周新增文档调用 `skylark_doc_detail` 获取正文，根据标题和内容进行分类：

**分类规则：**

| 分类 | 关键词/特征 | 示例 |
|------|------------|------|
| 工作总结 | PRD、TRD、需求、工单、排查、开发、项目、架构、设计文档、技术方案 | 「工单排查」XX问题、「需求开发」XX模块 |
| 集思录 | 学习、调研、DDD、AI、MECE、方法论、指南、总结、分析报告、业务梳理 | MECE学习指南、AI-Skills学习 |
| 无法分类 | 不明确属于以上类别 | 单独列出，让 agent 根据上下文判断 |

**注意**：一篇文档只归入一个分类，优先匹配「工作总结」。

### Step 4: 生成周报内容

按以下模版生成 Markdown 格式的周报。**核心原则：内容简洁，每个条目 1-2 句话概括即可，附上语雀文档链接。**

```markdown
本周核心目标：{根据本周文档内容提炼一句话核心目标}

# 工作总结
> 当涉及具体工作相关的内容（比如PRD、TRD、以及工单排查等内容），就记录在这里，如果没有，就不要这一块内容

## 「{工作类型}」{简短标题}
{1-2句话简要描述}

{语雀文档链接}

（如有多个工作项，重复以上格式）

# 集思录
> 当涉及业务、DDD、AI等相关的学习内容，就记录在这里，如果没有，就不要这一块内容

## {学习主题}
{1-2句话简要描述学习内容和收获}

{语雀文档链接}

（如有多个学习项，重复以上格式）

# 下周计划
> 根据本周工作内容推断下周可能的延续计划

1. {计划项1}
2. {计划项2}
3. {计划项3}

# 学习心得
{根据本周集思录中的学习内容，总结一段 100-200 字的学习心得体会，体现思考和沉淀}
```

**格式要求：**

- 工作总结中的标题使用「」标注工作类型，如「需求开发」、「工单排查」、「项目架构」
- 每个条目保持简洁，不超过 2-3 句
- 必须附上对应语雀文档的完整 URL
- 如某个分类下没有对应内容，直接省略该章节（不留空标题）
- 下周计划根据本周工作合理推断，列 2-3 条即可
- 学习心得需要有个人思考，不是简单罗列

### Step 5: 发布周报

1. 生成周报标题，格式：`周报 - {MM.DD}-{MM.DD}`（本周一到本周日的日期）
2. 调用 `skylark_doc_create` 将周报写入目标知识库：
   - `book_id`: Step 1 获取的知识库 ID
   - `title`: 周报标题
   - `body`: 生成的 Markdown 内容
   - `format`: "markdown"
3. 创建成功后，调用 `skylark_book_toc_update` 将新文档添加到知识库目录中（`action: "appendChild"`）
4. 将最终语雀文档 URL 返回给用户

### Step 6: 用户确认

将生成的周报内容展示给用户，包括：
- 周报内容预览
- 语雀文档链接
- 提示用户可以手动补充「下周计划」部分（因为这部分最好由本人填写）

## 注意事项

- 如果本周无新增文档，告知用户暂无可生成的内容
- 「下周计划」是基于本周工作的合理推断，提醒用户根据实际情况修改
- 保持内容精炼，避免大段复制文档原文，每个条目概括到 1-2 句话
- 文档链接务必使用语雀原始 URL，确保可点击访问
