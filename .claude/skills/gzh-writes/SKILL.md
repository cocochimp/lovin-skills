# 公众号编写发布Skill

## 触发方式

| 命令 | 行为 |
|------|------|
| `/gzh-writes` | 默认「商业」方向，全流程（选题→写文→配图→发布） |
| `/gzh-writes "具体主题"` | 跳过菜单，直接搜索该主题相关内容，进入全流程 |

## 交互入口

**1、无参数（`/gzh-writes`）：**
默认选择「商业」方向，直接进入 Step 1 → Step 2 → Step 3 → Step 4 全流程。

**2、有参数（`/gzh-writes "具体主题"`）：**
跳过菜单，启动 1 个 SubAgent 直接搜索该主题相关内容（不走固定渠道），进入全流程。

---

## Step 1：选题

### 选题偏好

- **人物驱动型优先**：5 个选题中至少 3 个以具体人物为切入点，即使底层话题是科技/商业
- 纯 AI 行业新闻（"XX 发布新模型"/"XX 融资"）不单独作为选题，必须用人物或利益冲突包装
- 每日最多发布 1 篇，避免同日多发稀释推荐权重

选题分两种模式，根据触发方式自动选择：

### 模式 A — 无参数（默认商业方向）

读取 `config/channels.json` 获取渠道列表，为每个渠道启动 1 个 SubAgent（Agent tool, subagent_type=general-purpose）并行抓取。

流程：并行抓取 → 汇总筛选 → 内部保留全部素材供"更换"使用 → 生成 5 条选题。

### 模式 B — 有参数（`/gzh-writes "xxx"`）

不走固定渠道抓取，启动 1 个 SubAgent 用 WebSearch + WebFetch 搜索该主题，获取 5-10 条结果并提取摘要，生成 5 条选题。

→ SubAgent prompt 和选题展示格式详见 `references/subagent-prompts.md`

## Step 2：写文

### 标题角度

用户选定选题后，分主观/客观两组各生成 5 个标题角度，共 10 个供选择：

```
### 主观角度（5个）
1. [标题] — 角度说明
...

### 客观角度（5个）
1. [标题] — 角度说明
...
```

展示后等待用户选定标题，选定后进入写作。根据所选标题所在分组（主观/客观）自动适配对应写作约束。

### 写作引擎规格

- **字数：** 700-900字（硬限制）
- **风格：** 根据所选标题的维度自动决定（见下方两套约束）

### 写作流程

1. **定结构**：
   - 主观模式：用3句话概括——核心论点是什么、用什么论据支撑、结尾走向哪里
   - 客观模式：用3句话概括——核心事实是什么、补充哪些信息、延伸什么方向
   - **正文分段要求**：正文必须使用 2-3 个分段进行论述，每段用加粗编号标题引领（如 `**一、xxx**`、`**二、xxx**`），每段围绕一个独立论据/视角展开
2. **搜素材**：启动 1 个 SubAgent（Agent tool, subagent_type=general-purpose）搜集数据/案例，**限制总工具调用不超过 30 次**。确保每个论据有具体支撑
3. **写初稿**：按所选维度的结构完成
4. **口语化检验**：逐句默读，拗口的改顺
5. **数据直觉化**：数据用直觉化表达——「接近一半」优于「47.3%」，「翻了三倍」优于「增长 312%」。精确数字只在核心论据处保留一个
6. **删废话**：每句话必须推进论点/信息，删掉不影响理解的句子
7. **字数检查**：确认700-900字范围内
8. **超字删减**：如果超过900字，砍掉最弱的论据段。这是公众号短文，不是长文深度报道，宁可少写一个点也不要全部蜻蜓点水

### 写作约束 —「主观看法」模式

- 开头即亮刀：第一句抛争议性观点或反常识结论
- 论据2-3个，以具体案例/故事为主，数据作为辅助点缀
- 语气像跟聪明朋友聊天，有逻辑骨架；善用反问、类比
- 结尾不总结，要么反转要么留一个值得深想的问题
- 重点强调：每篇文章必须有 2-3 处加粗（**强调内容**）和 3-4 处红色加粗（`**「重点内容」**`）。红色加粗标记每段最重要的一句（可以是数据、重点论述或核心结论），建议每个分段小标题下 1 处
- 禁止：空洞抒情、排比堆砌、"让我们一起xxx"、任何 AI 味表达

### 写作约束 —「客观说明」模式

- 开头用事实/数据/事件引入话题，不抛观点
- 内容以信息增量为核心：what happened → why → so what
- 论据以具体案例为主（公司/人名/时间），数据点缀，不做价值判断
- 语气克制中立，像一份高质量简报
- 可以在结尾点出"值得关注的方向"，但不下结论
- 重点强调：2-3 处加粗（**强调内容**）+ 3-4 处红色加粗（`**「重点内容」**`），建议每个分段小标题下 1 处，标记该段最重要的一句
- 禁止：主观评价（"我认为""显然"）、情绪化用词、煽动性表达

### 初稿展示 + 正文标题选择（合并确认）

写作完成后，**同时展示初稿内容和正文标题选项**，用户一次性确认内容并选标题：

```
## 初稿

[初稿正文内容]

---

请确认初稿内容，并选择正文标题：
1. 标题选项A
2. 标题选项B
3. 标题选项C
4. 标题选项D

> 回复标题编号确认，或提出修改意见
```

用户选定后写入 md 文件 frontmatter 的 title 字段。

### 输出

文件保存至：`docs/gzh/{YYYY-MM-DD}-{关键词}.md`

```markdown
---
title: 主体:标题（用户选定的正文标题）
date: YYYY-MM-DD
tags: [标签1, 标签2]
summary: 50字以内摘要
---

正文内容
```

## Step 3：配图

自主生成公众号专属配图，无需依赖外部技能。

| 用途 | 模板 | 规格 |
|------|------|------|
| 封面图 | `assets/cover_template.html` | 1080×608（16:9） |
| 数据图 | `assets/data_template.html` | 1080宽，高度自适应（fullpage截图） |

**封面图**：展示 3-5 组封面方案 → 用户选定 → 生成截图 → 自审
→ 详见 `references/cover-spec.md`

**数据图**：优先匹配子模板（对比/表格/时间轴） → 生成截图 → 自审
→ 详见 `references/data-chart-spec.md`

**图片自审**：每张图截图后必须执行 5 项检查，最多迭代 3 轮
→ 详见 `references/image-review.md`

封面图和数据图都通过自审后，**一次性展示两张图让用户确认**。

设计原则：
- 封面图：深色背景 + 大标题，简洁有力，远看能识别文字
- 数据图：浅色背景，商业质感，信息清晰，无多余装饰元素

## Step 4：发布

通过微信公众平台 API 将文章存入草稿箱（不会直接发布）。

展示发布清单 → 用户确认 → 执行 md2wx.js 转换 + publish.js 上传 → 输出草稿 media_id。

→ 详见 `references/publish-spec.md`

---

## 全流程执行说明

所有触发方式默认执行全流程（4 个确认点）：

1. 执行选题 → 展示5个选题 → **等待用户确认**（支持"更换"获取下一批）
2. 10个标题角度（主观5个+客观5个） → **等待用户选标题** → 写文 → 展示初稿 + 正文标题选项 → **等待用户确认内容并选标题**（合并确认）
3. 展示 3-5 组封面方案 → **等待用户选定** → 生成封面图 + 数据图 → 一次性展示两张图 → **等待用户确认配图**（合并确认）
4. 执行发布 → 输出完整发布包

每步之间必须有确认点，不要一口气跑完全流程。
