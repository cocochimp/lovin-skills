# 公众号内容生产技能

## 触发方式

| 命令 | 作用 |
|------|------|
| `/gzh` | 全流程（选题→写文→配图→发布），每步有确认点 |
| `/gzh 选题 [方向]` | 只出选题列表，方向可选：商业/思考/热点 |
| `/gzh 写文 [主题]` | 直接写文章 |
| `/gzh 配图 [文章路径]` | 为已有文章生成配图 |
| `/gzh 发布` | 输出发布就绪内容包 |

## Step 1：选题

**数据源（固定渠道）：**

| 渠道 | URL | 抓取目标 |
|------|-----|----------|
| 36氪 | https://www.36kr.com | 首页热门标题 5-10 条 |
| 财联社深度 | https://www.cls.cn/depth | 深度分析文章标题 5-10 条 |
| 微博热搜 | https://weibo.com/hot/search | 社会/泛热点 5-10 条 |

**流程：**
1. 并行启动 3 个 SubAgent（Agent tool, subagent_type=general-purpose），每个负责一个渠道的数据抓取
2. 汇总三渠道数据（约 15-30 条素材）
3. 如用户指定方向则聚焦筛选，否则综合推荐
4. 生成 5 个选题，每个包含：

**抓取策略（每个 SubAgent 内部执行）：**
1. 先用 WebFetch 抓取目标 URL，提取标题列表
2. 若 WebFetch 无效或返回空 → 降级 agent-browser（navigate + snapshot）
3. 均失败 → 返回空结果，由主流程基于已有知识补充，标注"未获取实时数据"

```
1. [标题]
   论点：一句话核心观点
   角度：切入视角说明
   争议点：可能引发的讨论方向
```

4. 等待用户选定后进入下一步

## Step 2：写文

### 写作引擎规格

- **字数：** 700-900字（硬限制，写完后检查）
- **风格：** 观点先行、论据锋利、口语化表达（详见 references/style-guide.md）

### 写作流程

1. **定结构**：用3句话概括——核心论点是什么、用什么论据支撑、结尾走向哪里
2. **搜素材**：用 WebFetch 搜集数据/案例（不可用时降级 agent-browser），确保每个论据有具体支撑
3. **写初稿**：按"亮刀→论据推进→反转/留问"结构完成
4. **口语化检验**：逐句默读，拗口的改顺
5. **删废话**：每句话必须推进论点，删掉不影响理解的句子
6. **字数检查**：确认700-900字范围内

### 写作约束

- 开头即亮刀：第一句抛争议性观点或反常识结论
- 论据2-3个，每个有数据或具体案例
- 语气像跟聪明朋友聊天，有逻辑骨架；善用反问、类比
- 结尾不总结，要么反转要么留一个值得深想的问题
- 禁止：空洞抒情、排比堆砌、"让我们一起xxx"、任何 AI 味表达

### 输出

文件保存至：`docs/gzh/{YYYY-MM-DD}-{关键词}.md`

文件格式：
```markdown
---
title: 文章标题
date: YYYY-MM-DD
tags: [标签1, 标签2]
summary: 50字以内摘要
---

正文内容
```

## Step 3：配图

复用 ljg-card 技能生成配图。

| 用途 | 调用方式 | 规格 |
|------|----------|------|
| 封面图 | ljg-card `-b` 大字模式 | 标题+核心论点，碑刻风格，1080x1440 |
| 文中数据图 | ljg-card `-i` 信息图模式 | 将关键数据/对比可视化 |

### 流程

1. 从文章提取封面标题（可以是文章标题的抓眼球变体）
2. 提取文中适合可视化的数据点（如果有）
3. 调用 ljg-card 对应模式生成

### 输出

- 封面：`docs/pic/gzh-cover-{YYYY-MM-DD}.png`
- 数据图：`docs/pic/gzh-data-{YYYY-MM-DD}-{n}.png`

## Step 4：发布

```
[完整 Markdown 正文]

### 封面图
路径：xxx

### 文中配图
- 图1路径：xxx（插入位置：第X段后）

### 摘要
[50字以内，用于公众号摘要字段]

### 检查项
- [ ] 标题是否抓眼球
- [ ] 封面图文字清晰
- [ ] 文中配图位置合理
- [ ] 摘要是否引发点击欲
```

## 全流程执行说明

当用户触发 `/gzh`（无子命令）时：

1. 执行选题 → 展示5个选题 → **等待用户确认**
2. 执行写文 → 展示初稿 → **等待用户确认/修改意见**
3. 执行配图 → 展示配图结果 → **等待用户确认**
4. 执行发布 → 输出完整发布包

每步之间必须有确认点，不要一口气跑完全流程。
