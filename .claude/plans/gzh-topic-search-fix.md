# 修改 `/gzh "xxx"` 的选题搜索逻辑

## 问题

当前 `/gzh "xxx"` 的行为是：5 个 SubAgent 抓取固定渠道 + 额外 1 个搜索主题。这不对。

正确行为：`/gzh "xxx"` 时，5 个 SubAgent 全部围绕该主题搜索，不走固定渠道抓取。

## 改动范围

文件：`.claude/skills/gzh/SKILL.md`

## 具体改动

### 1. 交互入口 - "有参数"说明

```
现在：跳过菜单，额外启动 1 个 SubAgent 搜索该主题（与渠道抓取并行），直接进入全流程。
改为：跳过菜单，启动 5 个 SubAgent 并行搜索该主题相关内容，直接进入全流程。
```

### 2. Step 1 流程部分

将流程改为两种模式：

**模式 A：无参数（选了方向）**
- 5 个 SubAgent 抓取固定渠道，每个 3-5 条标题
- 按用户选的方向筛选

**模式 B：有参数（`/gzh "xxx"`）**
- 5 个 SubAgent 并行搜索该主题（用 WebSearch + WebFetch）
- 不抓取固定渠道
- 每个 SubAgent 从不同角度/关键词搜索该主题

### 3. 删除"自定义内容搜索 SubAgent"独立小节

这个逻辑合并到模式 B 中，不再作为"额外"的补充。

### 4. 更新 SubAgent prompt 模板

模式 B 的 SubAgent prompt：
```
你的任务是搜索"{主题} + {角度关键词}"相关的最新资讯和深度分析。

步骤1：用 WebSearch 搜索，获取最新的 5-10 条相关结果。
步骤2：对最相关的 3-5 条，用 WebFetch 获取详细内容摘要。

输出格式：
1. 标题 | 链接URL | 一句话摘要
```

5 个 SubAgent 分别用不同搜索角度：主题本身、主题+行业影响、主题+争议观点、主题+数据案例、主题+最新动态。
