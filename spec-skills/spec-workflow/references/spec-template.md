# 业务 Spec 模板

当需要创建或更新 `spec.md` 时，使用以下模板。文件位于 `specs/<feature>/spec.md`。

## 定位

**业务契约**——用领域语言描述系统必须满足的业务规则和验收场景，作为编码的单一信息源。

| 该有的 | 不该有的 |
|--------|----------|
| 业务概念定义 | Java 代码 |
| 业务规则 BR-XXX（校验/计算/状态流转） | 技术选型（框架、中间件） |
| 业务场景 SC-XXX（GIVEN/WHEN/THEN） | 接口签名的技术细节（HTTP method、URL） |
| 约束 CON-XXX | Repository/Adaptor/Infrastructure |
| 领域模型字段表（按需） | 数据库表结构、PO 定义 |
| 状态机（业务视角） | 缓存方案、性能优化 |

## 编号规范

| 类型 | 格式 | 示例 |
|------|------|------|
| 业务规则 | `BR-<域缩写>-<三位数>` | `BR-BUY-001` |
| 业务场景 | `SC-<域缩写>-<三位数>` | `SC-BUY-001` |
| 约束 | `CON-<三位数>` | `CON-001` |

同一 spec.md 内编号递增不重复。

## 好的示例

```markdown
#### BR-BUY-003 采购单取消前置校验

**归属**：BuyOrderAggregate（聚合根） — 取消采购单前的状态校验

**输入**：当前 BuyOrder 状态

**逻辑**：

| 当前状态 | 允许取消 | 说明 |
|----------|----------|------|
| CREATED | 是 | 释放库存即可 |
| PENDING_PAYMENT | 是 | 取消付款请求 |
| PAID | 是 | 需触发退款流程 |
| COMPLETED | 否 | 已确认有房，不可取消 |
| CLOSED | 否 | 终态 |

**边界**：
- 并发取消 → 幂等处理，已取消的直接返回成功
```

## 坏的示例

```markdown
#### 取消订单

```java
@Transactional
public void cancelOrder(Long orderId) {
    BuyOrderAggregate order = repository.findById(orderId);
    if (order.getStatus() == COMPLETED) {
        throw new BizException("CANNOT_CANCEL");
    }
    order.setStatus(CLOSED);
    repository.save(order);
}
```

**问题**：出现了 Java 代码、事务注解、Repository 调用。这些是 design 或代码的内容，不属于 spec。
