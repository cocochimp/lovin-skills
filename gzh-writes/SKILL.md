# 公众号编写发布Skill

## 触发方式

| 命令            | 行为 |
|---------------|------|
| `/gzh-writes` | 默认「商业」方向，全流程（选题→写文→配图→发布） |
| `/gzh-writes "具体主题"` | 跳过菜单，直接搜索该主题相关内容，进入全流程 |

---

## 交互入口

**1、无参数（`/gzh-writes`）：**

默认选择「商业」方向，直接进入 Step 1 → Step 2 → Step 3 → Step 4 全流程。无需用户额外选择。

**2、有参数（`/gzh-writes "具体主题"`）：**

跳过菜单，启动 1 个 SubAgent 直接搜索该主题相关内容（不走固定渠道），进入全流程。

## Step 1：选题

选题分两种模式，根据触发方式自动选择：

---

### 模式 A — 无参数（默认商业方向）

**数据源（固定渠道，5 个渠道）：**

| 渠道 | URL | 方向 |
|------|-----|------|
| 36氪 | https://www.36kr.com | 综合/科技 |
| 财联社深度 | https://www.cls.cn/depth | 财经/时政 |
| 虎嗅 | https://www.huxiu.com | 商业/产业 |
| 钛媒体 | https://www.tmtpost.com | 科技/商业 |
| 界面新闻 | https://www.jiemian.com | 时政/财经 |

**流程：**
1. **并行抓取**：同时启动 5 个 SubAgent（Agent tool, subagent_type=general-purpose），每个使用 agent-browser 抓取对应渠道（见下方 SubAgent prompt）
2. 汇总所有素材，按商业方向聚焦筛选
3. 内部保留全部素材供"更换"使用
4. 生成 5 条选题

---

### 模式 B — 有参数（`/gzh-writes "xxx"`）

**不走固定渠道抓取**，直接搜索用户传入的主题。

**流程：**
1. 启动 1 个 SubAgent（Agent tool, subagent_type=general-purpose），用 WebSearch 搜索该主题，获取 5-10 条结果，对最相关的 3-5 条用 agent-browser 获取摘要
2. 从搜索结果中生成 5 条选题，以该主题为核心，从搜索结果中提炼角度（正面展开、对比分析、延伸联想等）

**给 SubAgent 的 prompt：**

```
你的任务是搜索"{用户传入主题}"相关的最新资讯和深度分析。

步骤1：用 WebSearch 搜索"{用户传入主题}"，获取最新的 5-10 条相关结果。

步骤2：对搜索结果中最相关的 3-5 条，使用 Skill 工具调用 agent-browser 技能，用浏览器自动化访问这些 URL 并提取内容摘要。

如果浏览器也失败，输出"抓取失败"。

输出格式：
1. 标题 | 链接URL | 一句话摘要
2. 标题 | 链接URL | 一句话摘要
```

---

### 渠道抓取 SubAgent prompt（模式 A 专用，5 个渠道统一使用）

~~~
你的任务是抓取 {URL} 的热门标题 3-5 条。

使用 Skill 工具调用 agent-browser 技能，然后用 agent-browser 提供的浏览器自动化能力：
1. navigate 到 {URL}
2. 等待页面加载完成
3. snapshot 获取页面内容
4. 从 snapshot 中提取标题列表

如果失败，返回"抓取失败"。

输出格式：每行一个标题，编号列出，每条附带文章链接（如能获取）。格式如下：
1. 标题文字 | 链接URL
2. 标题文字 | 链接URL
~~~

**选题展示格式：**

```
1. [标题]（36氪/财联社/虎嗅/钛媒体/界面新闻）
   URL（如有）
   论点：一句话核心观点
   角度：切入视角说明
   争议点：可能引发的讨论方向
```

5. 展示 5 条选题后，末尾提示：`💡 输入"更换"可获取下一批选题`
6. **"更换"机制**：用户输入"更换"时，从第一次抓取缓存的剩余素材中重新生成 5 条选题（无需重新抓取）
7. 等待用户选定后进入下一步

## Step 2：写文

### 标题角度

用户选定选题后，分主观/客观两组各生成 5 个标题角度，共 10 个供选择：

格式：
```
### 主观角度（5个）
1. [标题] — 角度说明
2. [标题] — 角度说明
3. [标题] — 角度说明
4. [标题] — 角度说明
5. [标题] — 角度说明

### 客观角度（5个）
1. [标题] — 角度说明
2. [标题] — 角度说明
3. [标题] — 角度说明
4. [标题] — 角度说明
5. [标题] — 角度说明
```

展示后等待用户选定标题，选定后进入写作。根据所选标题所在分组（主观/客观）自动适配对应写作约束。

---

### 写作引擎规格

- **字数：** 700-900字（硬限制）
- **风格：** 根据所选标题的维度自动决定（见下方两套约束）

### 写作流程

1. **定结构**：
   - 主观模式：用3句话概括——核心论点是什么、用什么论据支撑、结尾走向哪里
   - 客观模式：用3句话概括——核心事实是什么、补充哪些信息、延伸什么方向
   - **正文分段要求**：正文必须使用 2-3 个分段进行论述，每段用加粗编号标题引领（如 `**一、xxx**`、`**二、xxx**`），每段围绕一个独立论据/视角展开
2. **搜素材**：直接使用 Skill tool 调用 `agent-browser` 技能搜集数据/案例。确保每个论据有具体支撑
3. **写初稿**：按所选维度的结构完成
4. **口语化检验**：逐句默读，拗口的改顺
5. **删废话**：每句话必须推进论点/信息，删掉不影响理解的句子
6. **字数检查**：确认700-900字范围内
7. **超字删减**：如果超过900字，砍掉最弱的论据段。这是公众号短文，不是长文深度报道，宁可少写一个点也不要全部蜻蜓点水

### 写作约束 —「主观看法」模式

- 开头即亮刀：第一句抛争议性观点或反常识结论
- 论据2-3个，每个有数据或具体案例
- 语气像跟聪明朋友聊天，有逻辑骨架；善用反问、类比
- 结尾不总结，要么反转要么留一个值得深想的问题
- 重点强调：每篇文章必须有 2-3 处加粗（**强调内容**）和 3-4 处红色加粗（`**「关键结论或数据」**`），帮助读者快速抓取重点。加粗用于关键数据/结论，红色加粗用于核心判断句和重要数据
- 禁止：空洞抒情、排比堆砌、"让我们一起xxx"、任何 AI 味表达

### 写作约束 —「客观说明」模式

- 开头用事实/数据/事件引入话题，不抛观点
- 内容以信息增量为核心：what happened → why → so what
- 论据要求同主观模式（具体公司/人名/时间），但不做价值判断
- 语气克制中立，像一份高质量简报
- 可以在结尾点出"值得关注的方向"，但不下结论
- 重点强调：2-3 处加粗（**强调内容**）+ 3-4 处红色加粗（`**「关键结论或数据」**`）
- 禁止：主观评价（"我认为""显然"）、情绪化用词、煽动性表达

### 正文标题选择

写作完成后，生成 3-5 个正文标题选项供用户选择。

展示示例格式：
```
请选择正文标题：
1. 英伟达Q1财报拆解：营收441亿美元，同比增长69%
2. 贾跃亭又拿到7000万美元：骗子的信用为什么比你值钱？
3. 腾讯推不出豆包，不是技术问题
4. 马斯克输了1500亿的官司，他可能从没想赢
```

用户选定后写入 md 文件 frontmatter 的 title 字段。

### 输出

文件保存至：`docs/gzh/{YYYY-MM-DD}-{关键词}.md`

文件格式：
```markdown
---
title: 主体:标题（用户选定的正文标题）
date: YYYY-MM-DD
tags: [标签1, 标签2]
summary: 50字以内摘要
---

正文内容
```

## Step 3：配图

自主生成公众号专属配图，无需依赖外部技能。

| 用途 | 模板 | 规格 |
|------|------|------|
| 封面图 | `assets/cover_template.html` | 1080×608（16:9，公众号封面规范） |
| 数据图 | `assets/data_template.html` | 1080宽，高度自适应（fullpage截图） |

### 数据图参考类型

根据文章内容选择最合适的可视化类型：

- **对比卡片**：左右/上下对比布局，适合 A vs B 场景（如新旧方案、竞品对比）
- **数据表格**：行列清晰的结构化数据展示，适合多维数据（如财务指标、功能对比矩阵）
- **流程/时间轴**：纵向或横向的节点连线，适合事件演进、产品迭代、因果链

### 封面图流程

**封面方案选择（交互确认）：**

生成 3-5 组封面方案供用户选择，每组包含：
- 主标题（2行，第一行包含内容主体并设置悬念，第二行给出核心观点/结论，标注哪些关键词用红色高亮）
- 副标题（1行补充概述）
- 右侧背景数字（一个量化指标，如有）

注意：主标题必须是2行，且两行之间是递进关系——第一行点明内容主体（如公司名、人名、事件名）并引发好奇，第二行揭示答案。不能把一句话硬拆成两行。

展示格式：
```
请选择封面方案：

方案1:
  主标题:
    L1: 英伟达Q1：交出史上最强财报
    L2: <red>真正赢家</red>只有一个
  副标题: 英伟达Q1财报揭示算力经济新格局
  背景数字: $441B

方案2:
  主标题:
    L1: 英伟达：数据中心收入<red>暴涨73%</red>
    L2: 黄仁勋到底押对了什么
  副标题: 三条增长曲线背后的算力垄断逻辑
  背景数字: 73%

方案3:
  ...
```

用户选定后再执行以下步骤生成封面图。

**封面设计规范（三要素）：**
- **主标题**：固定2行（L1引发好奇 + L2揭示观点），部分关键词用红色（`var(--accent)` #E94560）标注，简洁吸引但不做标题党
- **副标题**：1 行补充概述，浅色（`var(--ink-light)`）
- **右下角背景数字（如有）**：一个量化指标（如 $441B、72%、10x），大字号低透明度（`rgba(accent, 0.15)`），作为视觉点缀

**生成步骤：**

1. 根据用户选定的封面方案，组装标题 HTML
   - 红色关键词用 `<span class="accent">关键词</span>` 包裹
   - **换行规则**：标题超过10个中文字时，手动用 `<br>` 分行，确保文字不溢出封面
2. Read `assets/cover_template.html`
3. 填充占位符：
   - `{{TITLE_HTML}}`：封面大标题（含红色标注的 span）
   - `{{SUBTITLE}}`：副标题文字
   - `{{CUSTOM_CSS}}`：自定义样式，包含右下角背景数字的实现：
     ```css
     .cover::after {
       content: "数字内容";
       position: absolute;
       right: 40px;
       bottom: 30px;
       font-size: 120px;
       font-weight: 900;
       color: rgba(233, 69, 96, 0.15);
       z-index: 0;
     }
     ```
4. Write 到 `/tmp/gzh_cover_{YYYY-MM-DD}-{关键词}.html`
5. 截图：`node .claude/skills/gzh-writes/assets/capture.js /tmp/gzh_cover_{YYYY-MM-DD}-{关键词}.html docs/pic/gzh-cover-{YYYY-MM-DD}-{关键词}.png 1080 608`
6. 执行「图片质量自审」流程（见下方自审章节）

### 数据图流程

1. 从文章提取适合可视化的数据/对比/流程
2. Read `assets/data_template.html`
3. 根据内容从零设计 CSS+HTML，填充：
   - `{{CUSTOM_CSS}}`：完整的自定义样式（布局、配色、排版）
   - `{{CONTENT_HTML}}`：数据可视化内容（图表、对比卡片、流程图等）
4. Write 到 `/tmp/gzh_data_{YYYY-MM-DD}-{关键词}.html`
5. 截图：`node .claude/skills/gzh-writes/assets/capture.js /tmp/gzh_data_{YYYY-MM-DD}-{关键词}.html docs/pic/gzh-data-{YYYY-MM-DD}-{关键词}-{n}.png 1080 800 fullpage`
6. 执行「图片质量自审」流程（见下方自审章节）

### 配图设计原则

- 封面图：深色背景 + 大标题，简洁有力，远看能识别文字
- 数据图：浅色背景，商业质感，信息清晰，无多余装饰元素
- 两者都保留噪点纹理增加质感，但不添加署名、编码等无关元素

### 图片质量自审

每张图片（封面图、数据图）截图完成后，**必须**执行以下自审流程，不可跳过：

#### 自审检查清单

| 检查项 | 通过标准 |
|--------|----------|
| 布局对齐 | 元素左右对称或对齐，间距均匀，无明显错位 |
| 字号层次 | 标题 > 副标题 > 正文 > 注释，大小区分清晰可辨 |
| 配色协调 | 主色不超过 3 种，对比度充足，无刺眼或冲突的配色 |
| 内容完整 | 文字无截断溢出，数据完整显示，无空白缺失区域 |
| 整体美感 | 整体看起来像专业设计的信息图，而非粗糙拼凑的截图 |

#### 自审流程

1. 截图完成后，用 Read 工具查看生成的 PNG 图片
2. 按上方 5 项检查清单逐项评估（通过/不通过）
3. **全部通过** → 展示给用户确认
4. **任一项不通过** → 定位 HTML/CSS 中的具体问题 → 修改 → 重新 Write HTML → 重新截图 → 再次自审
5. **最多迭代 3 轮**。3 轮后仍有不通过项 → 展示图片并标注已知问题，交由用户决定是否接受

#### 封面图 vs 数据图差异

- **封面图**：模板固定，重点检查文字截断和配色，通常 1 轮即通过
- **数据图**：CSS/HTML 自由度高，布局和配色问题更常见，是自审的主要价值所在

### 输出

- 封面：`docs/pic/gzh-cover-{YYYY-MM-DD}-{关键词}.png`
- 数据图：`docs/pic/gzh-data-{YYYY-MM-DD}-{关键词}-{n}.png`

首次使用需安装依赖：`cd .claude/skills/gzh-writes && npm install && npx playwright install chromium`

## Step 4：发布

通过微信公众平台 API 将文章存入草稿箱（不会直接发布）。

### 发布流程

1. **展示发布清单**（等待用户确认）：

```
## 发布清单

### 文章标题
xxx

### 封面图
路径：xxx

### 文中配图
- 图1路径：xxx（插入位置：第X段后）

### 摘要
[50字以内，用于公众号摘要字段]

### 检查项
- [ ] 标题是否抓眼球
- [ ] 封面图文字清晰
- [ ] 文中配图位置合理
- [ ] 摘要是否引发点击欲
- [ ] 声明原创
- [ ] 开启留言
- [ ] 群发通知（需后台手动操作）
- [ ] 定时发布时间（需后台手动设置）
```

2. **用户确认后**，执行自动发布到草稿箱：

```bash
# Step 1: Markdown → 微信兼容 HTML
node .claude/skills/gzh-writes/scripts/md2wx.js docs/gzh/{文章}.md /tmp/gzh_wx_{date}.html --image docs/pic/gzh-data-{date}-1.png:{段落位置}

# Step 2: 上传素材 + 创建草稿
node .claude/skills/gzh-writes/scripts/publish.js \
  --title "文章标题" \
  --content /tmp/gzh_wx_{date}.html \
  --cover docs/pic/gzh-cover-{date}.png \
  --summary "50字摘要" \
  --author "作者名" \
  --comment 1
```

3. **输出结果**：草稿 media_id + 发布后提示

> 草稿已创建并默认开启留言。如需声明原创、群发通知或定时发布，请前往 mp.weixin.qq.com 草稿箱操作。

### 配置前置条件

凭证与发布偏好存储在 `~/.gzh-config.json`（本地文件，不进代码仓库）：
```json
{
  "appId": "你的appId",
  "appSecret": "你的appSecret",
  "author": "你的署名",
  "original": 1,
  "reprint": 1,
  "comment": 1,
  "comment_audience": "all",
  "auto_select_comment": 1
}
```

字段说明：
| 字段 | 说明 | 默认值 |
|------|------|--------|
| appId/appSecret | 公众号开发者凭证 | 必填 |
| author | 作者署名 | - |
| original | 声明原创 (1=文字原创, 0=无需声明) | 1 |
| reprint | 快捷转载 (1=允许所有账号转载, 0=关闭) | 1 |
| comment | 开启留言 (1=开启, 0=关闭) | 1 |
| comment_audience | 谁可以留言 (all/fans/fans7) | all |
| auto_select_comment | 自动精选留言 (1=开启, 0=关闭) | 1 |

> 注意：original、reprint、auto_select_comment 目前无法通过 API 直接设置，脚本会在输出中提示用户去后台确认。

首次运行发布脚本时，若配置文件不存在，会输出完整模板引导用户创建。

需要在微信公众平台后台 → 设置与开发 → 基本配置 → IP白名单中添加本机 IP。

## 全流程执行说明

所有触发方式默认执行全流程：

1. 执行选题 → 展示5个选题 → **等待用户确认**（支持"更换"获取下一批）
2. 10个标题角度（主观5个+客观5个） → **等待用户选标题** → 写文 → 展示初稿 → **等待用户确认/修改意见**
3. 展示 3-5 个正文标题选项（`主体:标题` 格式） → **等待用户选定** → 写入 md 文件
4. 展示 3-5 组封面方案（主标题+标红词+副标题+背景数字） → **等待用户选定** → 生成封面图 → 数据图 → **等待用户确认**
5. 执行发布 → 输出完整发布包

每步之间必须有确认点，不要一口气跑完全流程。
